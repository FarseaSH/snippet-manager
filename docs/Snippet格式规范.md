# Snippet 格式规范

本文说明如何为 Snippet Manager 编写内容，规则与当前解析器一致。新建文件时可以直接复制下面的模板。

## 1. 文件与目录

| 对象 | 约定 |
| --- | --- |
| 内容目录 | 项目根目录下的 `snippets/`，支持任意层级的子目录 |
| Snippet | 一个 UTF-8 编码的 `.md` 文件，对应一个页面 |
| Folder | 文件所在的真实目录，用于分类；不通过标签指定目录 |
| Sub Snippet | 普通代码类型中，一个顶层围栏代码块对应一段可以单独复制的代码 |

未指定类型时使用普通代码 Snippet，下面第 2～7 节说明其编写方式。转换类型使用同样的 `.md` 文件、目录、名称和标签，新增配置见第 8 节。

例如，`snippets/linux/ssh-proxy.md` 属于 `linux` 分类。文件名决定页面路径，页面标题由文件中的 `snippet_name` 决定，两者可以不同。

推荐目录和文件名使用小写英文及连字符，例如 `python/files/read-json.md`，方便链接和版本管理。中文文件名也支持。改名或移动文件会改变页面地址，需要同步更新引用它的链接。

以 `.` 开头的文件、目录和符号链接不会被扫描。项目根目录的 `docs/`、`.pj/` 和 `README.md` 不会进入内容库。

## 2. 推荐模板：一个文件包含多个子片段

将下面内容保存为 `snippets/linux/ssh-proxy.md`。一个文件围绕一个主题，每个子片段描述一种具体用法。

````markdown
---
snippet_name: SSH SOCKS Proxy
snippet_tags: [linux, ssh, proxy]
---

通过 SSH 创建本地 SOCKS5 代理，供支持 SOCKS 的应用使用。

先执行 `:@Start Proxy`，再用 `:@Test with curl` 验证连接。

# Start Proxy

监听本机 1080 端口，`-N` 表示不执行远程命令。

```bash
ssh -N -D 127.0.0.1:1080 user@example.com
```

将 `user@example.com` 替换为你的登录用户和主机。

# Test with curl

使用代理请求网页，并让代理端解析域名。

```bash
curl --proxy socks5h://127.0.0.1:1080 https://example.com
```
````

页面标题为 **SSH SOCKS Proxy**，包含 **Start Proxy** 和 **Test with curl** 两个 Tab。第一个一级标题之前的文字显示在顶部总说明框；每段代码前后的文字显示在对应 Tab 下方、代码上方的独立说明框，随 Tab 切换，不再自动汇总到总说明中。上例中的 Tab 引用可以直接点击跳转。

## 3. Front Matter：两个必填字段

文件必须从 YAML Front Matter 开始，用两行 `---` 包住元数据。开头的 `---` 前不要添加标题、注释或空行。

```yaml
---
snippet_name: SSH SOCKS Proxy
snippet_tags: [linux, ssh, proxy]
---
```

| 字段 | 必填 | 类型与要求 | 用途 |
| --- | --- | --- | --- |
| `snippet_name` | 是 | 非空字符串，去除首尾空白后仍有内容 | 列表名称、页面标题和搜索 |
| `snippet_tags` | 是 | 字符串数组，可以是 `[]` | 标签展示和搜索 |
| `snippet_type` | 否 | `code` 或 `transform`，默认 `code` | 普通代码或文本转换器 |
| `transform` | 否 | 配置对象，仅转换类型使用 | 输入、输出的语言和示例文本 |

字段名及大小写必须保持一致。没有标签时也必须写 `snippet_tags: []`。重复标签会自动去重，未定义的其他字段不参与展示或分类。

标签也可以分行填写：

```yaml
snippet_tags:
  - linux
  - ssh
  - proxy
```

推荐同一类标签统一使用小写名称。含特殊字符、冒号，或者看起来像数字、布尔值的名称应使用引号，例如 `snippet_name: "JSON: 格式化"`、`snippet_tags: ["2026", "true"]`。

以下写法无效：

```yaml
snippet_name: ""               # 名称为空
snippet_tags: linux, ssh        # 这是字符串，不是数组
```

缺少任一必填字段、YAML 无法解析、重复 YAML 字段，或标签数组中含有非字符串值，都会导致这个文件被跳过。

## 4. 标题与子片段的对应关系

正文中的一级标题 `# 名称` 用于命名子片段，**不要把它当成整个页面的标题再写一遍**。页面标题已经由 `snippet_name` 提供。

- 每个一级标题只命名它后面、下一个一级标题之前的第一个顶层围栏代码块。
- 同一一级标题下再写第二个代码块，会创建另一个子片段，名称自动设为 `Untitled`。
- 所有没有关联一级标题的代码块依次命名为 `Untitled`、`Untitled 2`、`Untitled 3`，编号只计算这些未命名的代码块。
- 二级及更深的标题（`##`、`###`）属于说明内容，不用于命名子片段。
- 子片段按代码块在文件中出现的顺序展示。推荐每个代码块前写一个独立、明确的一级标题。

第一个一级标题之前的普通正文作为整个文件的说明。在一级标题之后，代码前的说明及代码后的补充归相应子片段；如果又出现一个代码块，后续说明改归这个新子片段，直到下一个代码块或一级标题。

如果一个一级标题后没有关联代码块，该标题及正文仍会保留。有其他代码块的文件会收到警告，不会丢失这部分内容。仅说明的文件不因使用一级标题而收到这种警告。

## 5. 代码块写法

使用三个或更多反引号，也可以使用三个或更多波浪号包住代码。推荐使用三个反引号，并填写小写语言标记：

````markdown
```python
import json

print(json.dumps({"ok": True}))
```
````

| 代码类型 | 推荐语言标记 | 常用别名 |
| --- | --- | --- |
| Python | `python` | `py` |
| JavaScript | `javascript` | `js` |
| TypeScript | `typescript` | `ts` |
| Bash / Shell | `bash` | `sh`、`shell` |
| Windows Batch | `bat` | 推荐直接写 `bat` |
| PowerShell | `powershell` | 推荐直接写 `powershell` |
| JSON / YAML / SQL | `json`、`yaml`、`sql` | YAML 也可写 `yml` |
| 纯文本 | `text` | 也可以不填写语言标记 |

语言标记用于语法高亮和图标选择，与目录、标签、子片段名称无关。未填写或无法识别的语言仍可展示和复制，使用可用的纯文本展示或默认图标。

围栏必须位于 Markdown 顶层，推荐顶格书写。**列表、引用中的围栏代码块，以及用四个空格缩进的代码块，只作为说明里的示例，不会生成子片段或 Tab。**

代码中保留实际需要的缩进和空行，不手动添加行号。命令示例一般不添加终端提示符 `$` 或 `>`，避免复制时把提示符一起带入。地址、用户名及参数可以使用明确的占位值，并在说明中解释如何替换。

“复制当前代码”只复制当前代码块的内容，包含其缩进和空行，不包含围栏、语言标记、一级标题或说明。页面顶部的“复制 Markdown”复制整个源文件，包括 Front Matter；Markdown 预览底栏的同名按钮只复制当前 Markdown 代码块的原文。

### Markdown 代码块预览

语言标记为 `markdown` 或 `md` 的子片段默认渲染预览。底栏语言名称后的按钮切换“源代码 / 预览”，内嵌代码块支持独立复制、行号和语言图标。

需要预览 Markdown 本身时，外层使用四个反引号，内部代码块使用三个反引号，避免提前结束外层围栏。完整示例见 [Markdown 预览示例](examples/markdown-preview.md)。

## 6. 只有一段代码，或只有说明

只有一个顶层代码块时，页面不显示 Tab 栏；总说明仍在顶部，属于该子片段的说明独立显示在代码上方，没有子说明时不留空框。例如保存为 `snippets/python/hello.md`：

````markdown
---
snippet_name: Python Hello
snippet_tags: [python]
---

打印一条消息。

# Hello

```python
print("hello")
```
````

没有顶层代码块也是有效 Snippet，正文完整展示，代码区按无代码内容处理，没有 Tab 或代码状态栏，不会因此报错。例如保存为 `snippets/guides/naming.md`：

````markdown
---
snippet_name: 命名约定
snippet_tags: [guide]
---

## 文件命名

推荐使用小写英文和连字符，例如 `read-json.md`。
````

空的顶层围栏代码块仍算一个子片段；如果只需要写说明，直接省略代码块即可。

## 7. 说明、链接和图片

说明支持普通 Markdown，包括段落、列表、引用、表格、行内代码、链接和图片。直接写 Markdown，不依赖自定义 HTML：原始 HTML 会按文本展示。

推荐开头用一两句话说明这个文件解决什么问题。中栏列表预览说明，最多显示一行。页面的总说明和当前 Tab 说明使用相同的描述框：短说明完整显示，长说明默认折叠为约五行，点击框体展开；展开后仅点击底部“收起”按钮折叠，不需要在源文件中手动截断。两个说明框独立展开、收起，各 Tab 在当前页面内记住自己的展开状态，切换到其他 Snippet 后重置。展开长说明时框内可以滚动，代码区仍保留阅读空间。

描述与 Markdown 预览中的普通行内代码可通过 `⌘ / Ctrl + 左键` 单独复制。

### 在说明中引用 Tab

将 `:@` 和目标 Tab 的完整名称一起放入行内代码，即可在总说明或任意子片段说明中插入跳转按钮：

```markdown
常规情况使用 `:@数组去重`，发送请求可参考 `:@GET Request`。
```

- 只引用当前文件中的子片段，名称对应一级标题生成的 Tab 名称。支持中文和空格，去掉引用名称的首尾空白后精确匹配，区分大小写；也可以引用写在后面的子片段。
- 渲染时隐藏 `:@`，显示目标代码的语言图标和 Tab 名称。点击后切换对应的说明和代码，并让目标 Tab 滚动到可见位置；不改变说明框的展开状态。只有一个子片段、没有 Tab 栏时也支持引用。
- 按钮支持键盘 Tab 聚焦、Enter / 空格激活。引用用于跳转，不参与普通行内代码的快捷复制。
- 找不到目标、名称为空或存在多个同名目标时，保留原始行内代码，并输出内容警告。修改 Tab 名称时，需要同步修改引用。
- 普通文本中的 `:@名称` 不会转换。代码块和 Markdown 代码预览内的内容保持原文；已包含在 Markdown 链接中的行内代码也保持原链接行为。

页面不再自动生成所有子片段的名称和说明列表。需要导航入口时，在总说明中显式写出上述引用即可。

### 代码占位符参数

在代码块中写 `@变量名[:类型及规则][:默认值]@`，页面会在当前 Tab 说明下方生成参数输入区。填写后实时替换当前代码，同名变量共用一个输入项。变量名区分大小写，支持中文、字母、数字、下划线及连字符，不能以数字开头。

| 写法 | 含义 |
| --- | --- |
| `@name@` | 文本，无默认值 |
| `@name::demo@` | 省略类型，默认文本 demo |
| `@name:text/^[a-z]+$/:demo@` | 文本，必须完整匹配正则 |
| `@port:number:8080@` | 数字，支持负数和小数，保留输入的写法 |
| `@port:number/^[0-9]{1,5}$/:8080@` | 同时满足数字类型及正则 |
| `@day:date:2026-11-10@` | 日期，默认输出 `YYYY-MM-DD` |
| `@day:date(YYYYMMDD):2026-11-10@` | 自定义日期输出格式 |
| `@start:date(YYYY-MM-DD HH:mm:ss):2026-11-10T14:30:25@` | 日期及时间，支持秒 |
| `@clock:date(HH:mm):09:05@` | 仅时间 |

类型仅支持小写 `text`、`number`、`date`，省略时按文本处理。正则直接接在类型后面，用 `/…/` 包裹，不加 `-`，第一版不支持正则修饰符；也可省略类型写成 `@name:/^[a-z]+$/:demo@`。正则内的斜杠需写成 `\/`，字符类内的斜杠可直接写。`date` 不允许接正则。

日期格式支持以下标记，区分大小写：

| 标记 | 含义 |
| --- | --- |
| `YYYY` / `YY` | 四位 / 两位年份 |
| `MM` / `M` | 月份，补零 / 不补零 |
| `DD` / `D` | 日期，补零 / 不补零 |
| `HH` / `H` | 24 小时制小时，补零 / 不补零 |
| `mm` / `m` | 分钟，补零 / 不补零 |
| `ss` / `s` | 秒，补零 / 不补零 |

中文及标点可以直接写；固定英文放在方括号里，例如 `date(YYYY-MM-DD[T]HH:mm:ss)`。参数名称旁不显示日期格式说明，输出格式仍由占位符语法决定。每个日期或时间变量使用一个输入框：点击打开选择弹层；同时需要日期和时间时，在同一弹层中选择日历和时间，包含秒时提供秒选择；仅时间格式不显示日历。同一变量多处使用不同日期格式时，共用输入，并合并各个位置对日期、时间和秒的需求：

```text
文件名：@start:date(YYYYMMDD_HHmm):2026-11-10T14:30@
正文：@start:date(YYYY年M月D日 HH:mm):2026-11-10T14:30@
```

默认值不随输出格式变化：日期使用 `YYYY-MM-DD`，日期时间使用 `YYYY-MM-DDTHH:mm` 或 `YYYY-MM-DDTHH:mm:ss`（日期和时间之间也接受空格），仅时间使用 `HH:mm` 或 `HH:mm:ss`。省略秒按零秒处理，不自动补今天、当前时间或缺少的日期、时间；按本地日历时间处理，不进行时区换算。

括号和正则内部的冒号不会分隔默认值，正则内部的 `@` 不会结束占位符。默认值中的冒号可直接写，字面量 `@` 写成 `\@`，例如 `@email:text:user\@example.com@`。输入值原样插入，不自动加引号、不递归解析输入内容；字符串所需的引号写在代码模板里。

无默认值且未填写、数字或日期无效、正则校验失败时，对应位置保留原占位符。未填写时仅显示红色输入框，不显示提示文字；格式有误时显示校验提示。用户主动清空文本输入时，会替换成空字符串。同名变量的类型和正则需一致；默认值可以只声明一次，多次声明时需一致（日期默认值按实际日期时间比较）。错误语法、无效格式、无效正则、默认值错误或同名冲突会输出内容警告，文件仍可正常阅读。

参数按 Tab 分开保存，切换 Tab 保留已填写的内容，切换 Snippet 后重置。“重置参数”只恢复当前 Tab 的默认值。编辑器、手机代码、Markdown 预览及其内嵌代码块复制使用同一份替换结果；顶部“复制 Markdown”和 Raw 地址始终提供原始文件。描述、标题和搜索索引不参与替换。

完整用例见 [占位符替换功能测试](examples/placeholders.md)。可复制到 `snippets/guides/placeholder-playground.md`，在页面逐项检查文本、数字、日期时间、多格式输出、独立 Tab 状态和 Markdown 预览。

库内链接和图片路径以**当前 Markdown 文件所在目录**为基准，例如在 `snippets/guides/organizing.md` 中：

```markdown
[Python Requests](../python/http/requests.md)
![内容流转示意](assets/workflow.svg)
```

其中图片实际位于 `snippets/guides/assets/workflow.svg`。链接指向有效 `.md` 文件时，会转换成该 Snippet 的页面地址；引用到的本地图片及其他本地资源会随站点打包。

本地资源放在 `snippets/` 内，推荐用非隐藏的 `assets/` 子目录管理。不要使用电脑上的绝对路径。资源缺失、链接指向不存在或被跳过的 Snippet、相对路径超出 `snippets/` 时会产生警告，当前文件仍可展示，但该链接或资源可能不可用。

外部网页可以正常使用 `https://` 链接。外部图片不会作为本地资源打包，离线使用时不保证可访问。

## 8. 转换类型：实时处理输入文本

声明 `snippet_type: transform` 后，页面固定显示“转换”和“转换代码”两个 Tab。“转换”显示左右排列的输入、输出编辑器，手机上改为上下排列；“转换代码”显示只读 JavaScript 源码，可复制和展开阅读。说明、目录、标签、搜索、页面链接与原始 Markdown 复制沿用普通 Snippet 的规则。

完整示例见 [JSON 格式化转换](examples/transform-json.md)，可复制到 `snippets/tools/json-format.md`：

````markdown
---
snippet_name: JSON 格式化
snippet_tags: [json, 转换]
snippet_type: transform
transform:
  input_language: json
  output_language: json
  example: '{"name":"demo","enabled":true}'
---

输入 JSON 文本，自动生成带缩进的结果。可通过 `:@转换代码` 查看实现。

# 转换代码

```js
export default function transform(input) {
  let value;
  try {
    value = JSON.parse(input);
  } catch {
    return { ok: false, error: { message: "请输入有效的 JSON 文本" } };
  }
  return { ok: true, output: JSON.stringify(value, null, 2) };
}
```
````

### 配置与代码结构

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `transform.input_language` | `text` | 输入编辑器的高亮语言 |
| `transform.output_language` | `text` | 输出编辑器的高亮语言 |
| `transform.example` | 无 | 示例字符串；填写后显示“填入示例”按钮 |

`transform` 及其各个配置均可省略。语言和示例必须是字符串；语言支持编辑器已有别名，未知语言按纯文本展示。多行示例可使用 YAML 的 `|` 写法。

每个转换 Snippet 必须包含且仅包含一个顶层 `js` 或 `javascript` 围栏代码块，语言标记不区分大小写。代码块提供第二个 Tab 的源码，固定标题为“转换代码”；`# 转换代码` 可省略。其他正文作为页面总说明，可使用 `:@转换` 和 `:@转换代码` 引用。源码中的 `@...@` 保持字面量，不创建普通代码的占位符参数区。

缺少 JS 代码块、多个顶层代码块、配置字段类型错误或未知 `snippet_type` 会产生内容错误并跳过该文件。函数入口、JavaScript 语法及返回结果错误在实际转换时显示，不影响其他 Snippet。

### 函数接口

代码块使用 `export default` 导出一个函数，函数名称可以自定。同一个代码块内可以编写辅助函数。输入参数是原始字符串，保留空格和换行；支持普通函数及 `async` 函数。

成功返回：

```js
return { ok: true, output: "转换后的纯文本" };
```

输入校验不通过时返回：

```js
return { ok: false, error: { message: "请检查输入格式" } };
```

`output` 必须是字符串，空字符串也是合法结果。`error.message` 必须是非空字符串。输出始终按文本显示，不解释为 HTML。直接抛出的异常、缺少默认函数或不符合上述接口的返回值，会显示为运行错误。

### 实时执行与状态

- 页面初次打开时输入为空，不自动执行；“填入示例”只填入文本，随后按相同的实时规则执行。
- 停止输入约 **500ms** 后自动转换。修改输入立即清除旧结果和旧错误，并取消尚未执行或正在执行的旧任务；异步旧结果不会覆盖新输入对应的结果。
- 空输入不执行、不报错；纯空白字符串仍会传给函数，由函数自行校验。成功但输出为空时仍可复制结果。
- 输入校验失败时输入框边框变红，下方显示错误，输出清空并禁用复制；运行异常和超时显示独立错误提示。
- 切换“转换 / 转换代码”保留输入和结果；切换到其他 Snippet 后重置。输入、输出不会写回 Markdown，也不会进入搜索索引。
- 转换在浏览器本地隔离环境执行，支持离线使用；运行不能访问页面 DOM、站点存储和网络，不支持外部依赖或远程模块。每次运行最长 **2 秒**，超时终止以保持页面可操作。
- 内容扫描、构建、搜索和仅浏览源码时，不执行转换函数。顶部“复制 Markdown”和 Raw 地址始终提供原始文件；代码 Tab 复制 JS 源码，转换 Tab 只复制输出字符串。

## 9. 可选：目录排序与图标

创建真实目录即可产生分类，不必先登记。页面显示名称保留目录原始大小写、下划线和连字符，不自动将首字母或缩写大写。需要调整目录顺序或指定图标时，编辑 `snippets/_folders.yml`：

```yaml
folders:
  - linux[bash]
  - python[python]:
      - http
      - files:
          - json[json]
  - git
```

`folders` 的每项使用真实目录名，末尾可追加 `[图标标记]`；有子目录时加 `:` 并使用嵌套数组设置该目录下的子目录顺序。叶子目录可以直接写 `- linux[bash]`，也可以写 `- linux[bash]:`。未配置的目录仍会显示，并按名称排列在已配置目录之后。配置不创建目录，也不控制 Snippet 顺序。

图标直接写在目录名末尾的中括号内：

- 中括号前是该层的真实目录名，不写完整路径。例如 `python[python]` 对应 `snippets/python/`，嵌套的 `json[json]` 对应 `snippets/python/files/json/`。实际目录名称与页面显示名称不包含图标标记。
- 标记使用 `python`、`javascript`、`typescript`、`bash`、`json` 等，不带文件扩展名前的 `.`；支持 `py`、`js`、`ts`、`sh` 等别名，忽略标记的大小写及首尾空格。
- 子目录继承最近一个已配置父目录的图标。上例中 `python/http`、`python/files` 使用 Python 图标，`python/files/json` 及其子目录使用 JSON 图标。
- 没有自身或父目录配置时统一使用普通文件夹图标，不随展开或选中状态改变。空标记或不支持的标记会产生警告，仅忽略该图标，目录排序、子目录配置及父目录图标继承仍有效；不存在的目录会产生警告，该目录项忽略。
- 左侧目录树、中栏每个 Snippet 的路径图标、窄屏目录选择按钮和手机子目录入口使用同一套规则。路径图标根据 Snippet 实际所属目录显示，不随当前搜索或父目录筛选范围改变。

`_folders.yml` 与 `folders` 均可省略；目录排序和图标共用这一个配置字段。保存后开发页面实时更新；部署时图标配置随静态数据一起发布。

Snippet 列表按 `snippet_name` 排序，同名时按路径排序。浏览父目录时，列表同时包含直属和所有子目录下的 Snippet。

## 10. 保存与检查

开发时执行 `npm run dev`，添加、修改或删除 `snippets/` 中的文件会自动更新页面，不需要先构建数据。发布时执行 `npm run build`，生成一次静态内容。

写完一个文件后，检查以下内容即可：

1. 文件出现在正确目录，页面名称和标签符合预期。
2. 每个顶层代码块都有预期的名称、语言和顺序。
3. 当前代码复制后保留所需缩进，没有多余提示符或手写行号。
4. 总说明与每个 Tab 的说明归属正确，Tab 引用可跳转，链接和图片可以访问。
5. 开发或构建控制台没有该文件的格式错误；错误文件会被跳过，其他有效文件仍继续处理。

现有示例可参考 [SSH SOCKS Proxy](../snippets/linux/ssh-proxy.md)、[Git Branch](../snippets/git/branch.md) 和 [仅说明片段](../snippets/guides/organizing.md)。
